- Bugfix — embedded team builder rendered at zero height on `roster_screen.tscn`: **COMPLETE** — 2026-07-17. Reported by Rob from real windowed play. Root cause, confirmed via a real non-headless screenshot: `team_builder_screen.tscn`'s root `Control` is anchor-laid-out (correct for its two established top-level usages), but `roster_screen.gd` embeds it as a child of a `VBoxContainer` — in Godot 4 a `Container` always overrides a Control child's position/size via `custom_minimum_size`/`size_flags`, which the builder's root had never needed to set before, collapsing its rendered height to 0. Fixed with 2 lines in `roster_screen.gd`'s own embedding call site (`custom_minimum_size = Vector2(0, 1000)` + `size_flags_vertical = SIZE_EXPAND_FILL`) — `team_builder_screen.tscn` itself untouched, since its other 2 usages never went through a `Container` and were never affected. Confirmed via grep this is the ONLY place any screen scene is embedded as a child rather than swapped in via `change_scene_to_file` — every other M23 navigation path is categorically unaffected. Root-caused why `m23_5_team_persistence_test.gd` (which DOES exercise the exact buggy code path) never caught this: every existing assertion checked logical/state correctness only, never the resulting Control's actual rendered size — closed with a new `S2.02b` assertion, proven to actually catch the regression (reverted the fix, reran, got the expected failure; restored, reran clean). Regression: 143 files, GRAND TOTAL 13790→13791 (+1, exactly the new guard assertion), zero other differences across 2 sweeps.
